# 제한 실행기 실험 — 2026-10-27

이 브랜치는 실험용이다. 전용 Sol 검토기의 실행 도구를 제거하고, 호스트가 실제 검사와 한 번의 수정 전달을 수행한다. 일반 Paseo 시작 대화의 도구는 제한하지 않는다. 준비·대기·검토를 모델이 매번 다시 결정하는 왕복을 줄이는 데 보존할 가치가 있지만, 전체 비용 절감이나 기능 완성으로 발표할 단계는 아니다.

## 실제 실행 1회

동일 ledger 시작 커밋·계약·고정 외부 평가기를 사용했다. Sol 6.1 high, Merge Gateway DeepSeek V4.1 Flash high이며 자동 재시도는 없었다. 같은 워커를 한 번 수정하고 같은 검토 스레드를 재개했다.

| 항목 | 관측 |
| --- | --- |
| 전용 Sol 실제 제공자 응답 | 2회 |
| 전용 Sol 입력 / 출력 | 42,594 / 1,501토큰 |
| 전용 Sol 합계 | 44,095토큰; 캐시 0, 추론 1,201은 출력의 부분집합 |
| 전용 Sol 도구 호출 | 0회 |
| DeepSeek 응답 | 91회; 입력 사용량 누락으로 총량 `null` |
| 실행 시간 | 19분 45초 |
| 고정 외부 / 공개·추가 테스트 | 24/24, 31/31 통과 |
| 별도 확인 | 5,000자리 금액과 긴 한글 메모 통과; 공백/탭 한 필드 행은 잘못 허용 |
| 판정 | 실행 통제 PASS, 기능 FAIL, 팀 사용량 INCOMPLETE |

직전 일반 Sol 조율은 7회·223,842토큰이었다. 전용 검토기만 보면 80.3% 적지만 역할과 집계 범위가 달라 전체 절감률이 아니다. 기존 준비·실험·집계 대화도 최종 답변 전 시점까지 15회·1,493,336토큰을 사용했다. 이 대화의 수치는 완료 합계가 아닌 관측 부분합이다. 워커 입력이 누락돼 팀 전체량과 청구 금액은 계산하지 않았다.

다음 전체 경로 측정은 아래에 기록한다. 토큰에는 캐시 입력을 포함하며 캐시·추론을 중복 합산하지 않는다. 설치·개발·계측 준비 대화는 별도로 공개한다. 이전 단독 실행은 새 대응 실험이 아니다.

## 새 시작 대화부터 최종 보고까지의 전체 경로 1회

커밋 `7235563`을 설치하고 동일한 시작 커밋·과제·평가기와 두 문장 요청으로 새 독립 Sol 대화를 만들었다. Sol high와 Merge DeepSeek high를 사용했다. 시작·계약 읽기·대기 재개·중단 보고·사용자 승인 뒤 재개·최종 보고를 모두 집계했다. 새 실험을 다시 시작하거나 새 워커로 교체하지 않았다.

| 역할 | 실제 응답 | 캐시 포함 토큰 |
| --- | ---: | ---: |
| 시작·대기·보고 Sol | 28 | 964,422 |
| 전용 Sol 검토기 | 2 | 45,300 |
| **실험의 Sol 합계** | **30** | **1,009,722** |
| DeepSeek | 55 | 입력 누락으로 `null`; 보고된 출력 부분합 48,220 |

전체 경과 시간은 승인 중단을 포함해 15분 5초였다. 고정 외부 평가 24/24, 공개·추가 테스트 38/38, 별도 공백 행과 긴 입력 검사 모두 통과했다. 기능은 PASS, 사용량 절감은 FAIL, 팀 전체 사용량은 INCOMPLETE다. 직전 일반 조율 223,842토큰의 4.51배이며 과거 Sol 단독 125,326토큰의 8.06배다. 새 단독 대응 실험이나 중단 없는 실행의 성능 차이로 해석하지 않는다.

증가 원인을 요청 기록에서 확인했다.

- 시작 Sol이 스킬 예제의 긴 `functions.exec` 대기 pragma를 빠뜨렸다. 대기 재개만 최초 구간 12회, 승인 뒤 6회로 총 18회 발생했다. 전용 검토기에 도구가 없어도 시작 대화의 행동은 강제되지 않는다.
- 자동 승인 검토가 과제·전체 패치·테스트를 전용 Sol 프로세스에 전달하는 명시적 승인 부족을 이유로 중단했다. 중단 시점은 17회·434,605토큰이었다. 실험 대화에 실제 사용자 `승인` 입력이 들어온 뒤 같은 실행을 계속했다. 중단과 재개 비용도 모두 포함했다.
- 시작 Sol은 중단 후 증거·실행기 소스를 추가로 읽고, 보존된 검토 단계부터 이어가도록 실행기 코드를 메모리 안에서 조정했다. 패키지에 정식 재개 기능이 있는 것은 아니며, 이 경로를 검증된 정상 실행으로 취급하지 않는다. 저장소·설치 파일은 바뀌지 않았다.

개발·커밋·푸시·계측을 수행한 기존 대화도 별도로 집계했다. 결과 수집 시점까지 22회·3,008,623토큰이었으며, 그 대화의 최종 응답 전 부분합이다. 위의 새 실험 Sol 합계에 이 개발 대화는 포함되지 않는다. 따라서 작업 전체의 토큰 감소나 청구 비용 절감을 주장하지 않는다.

전용 Sol은 두 요청에서 도구 호출 0회였고, 같은 워커의 한 번 수정으로 기능을 완성했다. 보존 검사 대상 523개 경로는 허용된 실험 폴더 신뢰 등록 이외 변경이 없었다. 원시 로그 대신 비밀·본문을 제외한 [집계와 근거 해시](gated-full-usage-20261027.json)를 함께 보존한다. 시작 대기와 승인 후 재개가 실행기에서 제어되기 전까지 이 브랜치를 비용 절감용 기본 배포로 권하지 않는다.

## 재현 범위와 제약

- 오프라인 검사 68개가 통과했다. localhost SSE 재생으로 실제 native Codex의 최초 요청과 같은 스레드 재개 요청에서 도구 목록이 비어 있음을 확인했다. 실제 제공자 호출은 이 재생에 포함되지 않는다.
- `scripts/sol-tool-audit.json`은 검사된 `codex-cli 0.162.1` 바이너리 해시와 정책에 묶여 있다. 다른 CLI에 맞추려고 해시만 교체하거나 검사를 우회하지 않는다. 도구 목록의 native 재생 검증이 새로 필요하다. 이 브랜치에는 범용 자동 재검사 도구가 포함되지 않았다.
- 각 실행의 `skillDir`은 실제 설치 절대 경로로 전달한다. 모델·추론·프로필 불일치나 검사 실패 시 다른 경로로 자동 전환하지 않는다. 프로필 기본 max는 이번 high 실험을 위해 변경하지 않았다.
- native CLI의 재개 후 `turn.completed` 사용량은 스레드 누계였다. 해당 필드를 회차별로 더하지 않고 고유 `token_usage_record.response_id`별 사용량을 합쳐 최종 누계와 대조했다.
- 실제 운영 흐름 승인과 독립 평가 결과를 구분한다. 이번 Sol은 남은 공백 행 결함을 발견하지 못했다.
- 디렉터리 분리는 협조적 실험 경계이며 워커 후손 프로세스의 OS 격리를 입증하지 않는다.
- 인증·프로필·제공자 설정과 기존 스킬 등 검사 대상 517개 파일은 그대로였다. 원시 세션·인증·후보 구현은 이 배포 저장소에 포함하지 않는다.
