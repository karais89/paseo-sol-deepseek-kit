# 검증 근거와 적용 한계

이 문서는 과거 운영안의 기록이다. 이 실험 브랜치의 호스트 실행기와 도구 없는 Sol 검토 결과는 [2026-10-27 실험 기록](gated-experiment.md)에 별도로 기록한다. 과거 69~71%와 새 전용 검토기 수치를 같은 범위의 절감으로 비교하지 않는다.

2026-10-25까지의 개인 ledger/calendar 실험을 요약한 것이다. 재현용 벤치마크·평가기·원시 로그는 이 배포 저장소에 포함하지 않았다. 아래 수치는 다른 환경의 성능 보장이 아니다.

2026-10-26 사용자 요청으로 운영 프로필을 Sol `high`, DeepSeek V4.1 Flash `max`로 정했다. 아래 과거 실험은 DeepSeek `high` 기준이며 새 `max` 설정의 성능·토큰 사용량을 검증한 결과가 아니다.

| 비교 | 관측 | 한계 |
| --- | --- | --- |
| 과거 Sol 단독 A | Sol 평균 216,620토큰 | 과거 실행 기준선 |
| Sol 계획·별도 Sol 검토 E | Sol 평균 62,638, 약 71% 감소 관측 | 전체 구현 4회 중 워커 사용량 누락 1회로 엄격한 전체 판정 실패 |
| 같은 Sol 계획·검토 F | Sol 평균 66,168, 약 69% 감소 관측 | 기존 제출물 4회 재생; 새 워커 구현과 대기를 포함하지 않음. 비캐시는 A보다 약 47% 증가 |
| 추가 리뷰 워커 진단 v3 | 유효 대응 10쌍에서 Sol 총 +0.35%, 시간 약 +48%, 추가 워커 평균 45,433 | 24회 중 22회만 완료. 고정 소스 리뷰 진단이며 전체 개발 비교가 아님 |

기본 운영안은 같은 Sol 대화의 계획·최종 리뷰, 지속 DeepSeek 워커, 변경분 중심의 검토 자료, 알림 기반 대기다. 추가 리뷰 워커는 필수가 아니며 최종 Sol 수락 책임은 유지한다. 선택적 추가 리뷰나 병렬 워커의 성능 효과는 별도로 검증하지 않았다.

같은 세션이어도 캐시 적중을 보장하지 않는다. 제공자 간 토큰 합을 청구 비용으로 해석하지 않는다. 전체 운영 토큰 절감·비용·실행 시간·실패율을 확정하려면 동일 시작 상태와 고정 검증 조건에서 새 워커 구현과 실제 대기까지 포함해 반복 측정해야 한다.

이 배포본은 역할 절차를 이식하기 위한 것이다. 실험의 계측 플러그인이나 자동 실행 제어기를 배포한 것이 아니다. 설치 검증과 실제 모델 행동·성능 검증을 구분한다.
